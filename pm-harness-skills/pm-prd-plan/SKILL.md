# pm-prd-plan

把已经确认的产品定位转化为可执行、可审计、可交接的产品规划基线。

## 核心边界

- 上游输入：`pm-prd-position` 的产品定位基线包。
- 本 Skill：规划产品域、功能模块、核心能力、里程碑、功能项、范围、依赖与风险。
- 下游输出：供 `pm-prd-design` 使用的规划基线和设计输入说明。
- 禁止进入：页面、导航、字段、组件、视觉、交互、原型、接口、数据表、详细状态机、验收用例和研发任务拆解。
- 发现上游定位缺失或互相冲突时，暂停对应规划主题并要求补齐或回到定位阶段；不得自行虚构定位结论。
- 用户要求越界内容时，先完成规划交付，再明确建议切换到 `pm-prd-design`。

## 选择运行模式

1. **首次规划**：最低输入为完整产品定位基线包。
2. **重新规划**：最低输入为现有规划基线包、重新规划原因和目标；重新评估整体规划。
3. **局部 Patch**：最低输入为现有规划基线包和明确变更诉求；先分析直接与连带影响，等待用户确认修改范围，再修改。

开始前读取 [references/workflow.md](references/workflow.md)。生成文件时读取 [references/output-contract.md](references/output-contract.md)。进行重新规划或 Patch 时还必须读取 [references/change-governance.md](references/change-governance.md)。

## 工作原则

- 默认按主题分轮反问，每轮聚焦 1–3 个关键决策；允许根据答案动态跳转、追问和回溯。
- 每个问题提供互斥选项、推荐项、推荐理由和主要风险，并允许自由补充。
- 对未经验证的假设、范围膨胀、版本目标与功能不匹配、依赖缺失主动提出挑战。
- 与用户判断冲突时，展示依据、影响和风险，持续讨论直到形成一致结论；不得用“用户说了算”绕过冲突。
- 每个关键决策节点记录：问题、候选项、推荐、依据、风险、用户选择、最终结论、影响对象和追踪标识。
- 建立 `定位结论 → 规划决策 → 架构/里程碑/功能项` 的显式追踪关系。
- 不以“文档已生成”作为完成标准；必须通过闭环完整性检查。

## 规划顺序

默认按以下主题推进，必要时动态调整：

1. 校验定位输入和规划目标。
2. 映射定位结论、用户价值、业务目标与规划约束。
3. 构建产品能力地图：产品域 → 功能模块 → 核心能力。
4. 明确系统内外边界及域、模块、能力之间的依赖。
5. 设计业务目标驱动的里程碑，定义每阶段范围、成果与退出标准。
6. 以退出标准反推每个里程碑的最小必要范围。
7. 建立功能清单：模块 → 能力 → 功能项。
8. 综合业务价值、用户价值、战略匹配、风险、成本与依赖评估优先级。
9. 识别业务、能力、数据、技术、组织和外部依赖与风险。
10. 完成追踪、决策、差异、设计交接和完整性检查。

不得机械地一次提出全部问题。已有结论充分时直接复用并记录来源，不重复询问。

## 核心产出规则

### 产品架构

- 层级固定为：产品域 → 功能模块 → 核心能力。
- 使用 Mermaid 架构图、分层文字说明、边界表和依赖表共同表达。
- 架构图呈现产品逻辑结构，不画页面结构、技术部署拓扑或数据库结构。

### 产品里程碑

- 按业务目标分阶段，不按固定时间或功能堆叠机械切分。
- 每个里程碑必须包含：业务目标、目标用户、最小必要范围、明确不做、关键成果、前置依赖、风险、验证指标和退出标准。
- 未满足退出标准时，不默认进入下一里程碑。

### 产品功能清单

- 层级固定为：模块 → 能力 → 功能项。
- 每个功能项至少标注：标识、价值、优先级、目标里程碑、依赖、边界、来源定位结论和状态。
- 优先级必须有多维依据，不允许仅凭 P0/P1/P2 标签。
- 功能项描述“产品提供什么能力”，不得写成页面控件、字段定义或交互步骤。

### 依赖与风险

- 覆盖业务、能力、数据、技术、组织、外部六类。
- 记录影响对象、影响程度、发生可能性、等级、应对措施、触发条件和责任建议。
- 技术风险只描述规划约束和能力依赖，不展开实现方案。

## 关键检查点

在以下节点获得明确确认后继续：

- 规划目标与范围边界。
- 产品架构及系统边界。
- 里程碑目标、最小范围和退出标准。
- 功能优先级及版本归属。
- 高等级依赖与风险的处理策略。
- 重新规划或 Patch 的最终修改范围。
- 最终规划基线。

## 交付

从 `assets/planning-baseline-template/` 复制模板，按实际内容完整填写，不保留占位符。默认生成：

```text
<product>-planning-baseline-v<version>/
├── 00-规划总览.md
├── 01-产品架构.md
├── 02-产品里程碑.md
├── 03-产品功能清单.md
├── 04-范围与边界.md
├── 05-依赖与风险.md
├── 06-规划决策记录.md
├── 07-版本差异.md
└── 08-产品设计交接说明.md
```

- 首次规划的 `07-版本差异.md` 记录“首次建立基线”，不得删除。
- 输出完整 Markdown 多文件目录，并打包为同名 ZIP。
- 运行 `scripts/validate_baseline.py <规划基线目录>`；校验失败时修正后重新运行。
- 最终交付前人工核对定位映射、架构、里程碑、功能范围、依赖风险、决策和设计输入是否闭环。

## 完成标准

仅当以下条件全部满足时结束：

- 产品架构图、里程碑、功能清单均完整且相互一致。
- 关键定位结论可追踪到规划决策及至少一个规划产物。
- 每个里程碑范围可由业务目标和退出标准解释。
- 功能项具有价值、优先级、版本、依赖与边界。
- 高等级依赖与风险均有应对及责任建议。
- 所有关键决策已逐节点确认并记录。
- 重新规划或 Patch 已记录影响、确认范围和版本差异。
- 设计交接说明给出明确输入，同时不包含详细产品设计。
- 自动校验通过，Markdown 目录和 ZIP 均已生成。
