# 规划工作流

## 目录

1. 启动校验
2. 分主题推进
3. 决策节点
4. 优先级评估
5. 完整性收口
6. 异常处理

## 1. 启动校验

### 首次规划

确认定位基线至少包含：目标用户、核心场景、用户问题、核心价值、差异化、业务目标、产品边界、关键约束、验证结论与未决事项。缺少会改变规划方向的内容时，停止对应主题，要求补齐定位。

### 重新规划

确认现有规划基线、触发原因、预期目标、外部变化、已验证结果和必须保留的约束。先判断是整体重构还是局部调整，不能把重新规划默认等同于全部推翻。

### 局部 Patch

确认当前基线版本、明确修改点、保持不变项和期望版本号。先输出影响分析，用户确认范围前不得改写基线。

## 2. 分主题推进

默认主题：

1. 规划目标与成功标准
2. 定位到规划的映射
3. 产品域与能力地图
4. 内外边界和依赖
5. 阶段业务目标
6. 里程碑范围与退出标准
7. 功能项与优先级
8. 风险及责任建议
9. 追踪、交接与验收

每轮只问会改变规划结论的问题。已从定位基线明确得到的事实直接引用；推断必须标注并让用户确认。

## 3. 决策节点

每个关键决策采用以下结构：

- 决策 ID：`DEC-PLAN-XXX`
- 主题与问题
- 已知事实
- 候选项（互斥）
- 推荐项
- 推荐依据
- 主要风险
- 用户选择
- 冲突与挑战过程
- 最终结论
- 影响：架构、里程碑、功能、边界、依赖风险
- 来源定位 ID
- 确认日期

若用户选择与推荐冲突，继续讨论依据与影响。只有形成一致结论后才标为“已确认”；仍有真实外部不确定性时可标为“条件确认”，同时给出验证条件和回退点。

## 4. 优先级评估

分别评估：

| 维度 | 判断重点 |
| --- | --- |
| 业务价值 | 收入、效率、成本、风险或战略结果 |
| 用户价值 | 问题强度、频率、覆盖与体验提升 |
| 战略匹配 | 是否支撑定位和当前阶段目标 |
| 风险 | 合规、市场、不确定性和机会成本 |
| 成本 | 复杂度、资源和持续运营负担，仅作规划级估计 |
| 依赖 | 是否是其他能力或里程碑的前置条件 |

输出综合结论和依据。若使用数值评分，评分只能辅助判断，不得替代产品决策。优先级建议采用 `P0/P1/P2/P3`，并说明：

- P0：当前里程碑退出不可缺少。
- P1：显著提升达标概率，资源允许应纳入。
- P2：有价值但可延后，不影响当前退出。
- P3：观察或储备，不进入已承诺范围。

## 5. 完整性收口

逐项检查：

- 每条关键定位结论是否映射到规划决策。
- 每个产品域是否有边界和责任说明。
- 每项核心能力是否归属唯一主模块，跨域依赖是否注明。
- 每个里程碑是否有业务目标、最小范围、指标和退出标准。
- 每个 P0 功能项是否直接支撑所在里程碑退出标准。
- 每个功能项是否有来源、价值、优先级、版本、依赖和边界。
- 每个高等级风险是否有应对、触发条件和责任建议。
- 设计交接是否完整且没有越界进入设计。

## 6. 异常处理

- 定位结论冲突：返回上游定位决策，不擅自选择。
- 功能无法映射定位或里程碑：移出承诺范围，进入候选池或删除。
- 里程碑范围过大：以退出标准反推最小闭环，拆分后重新确认。
- 用户直接要求功能堆叠：先追问对应业务目标和用户价值。
- 技术方案讨论过深：记录为技术约束或待研发评估项，停止实现设计。
- 页面或交互诉求：记录为设计输入，交给 `pm-prd-design`。
