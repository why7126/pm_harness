# 运行模式

## 首次收敛

最低输入为 `pm-prd-plan` 完整规划基线。先确认目标时间、预算、人力和资源容量，再按主题推进。

## 重新收敛

最低输入为现有 MVP 基线包、重新收敛原因与目标、已获得的验证结果。保留仍有效结论；分析失败假设、变化来源和影响范围，再决定主版本或次版本升级。

## 局部 Patch

先列出请求项、直接影响、连带影响、允许修改项与锁定项，由用户确认范围后修改。修订号递增并生成版本差异记录。不得借 Patch 无授权优化其他内容。

## 反问规则

- 默认每轮 1–3 个同主题关键问题，采用结构化选项、推荐项和自由补充。
- 推荐项必须包含理由和主要风险。
- 回答暴露新假设或冲突时动态追问；已确认内容不重复询问。
- 与用户判断冲突时展示证据、评分、闭环影响、成本风险和替代方案，持续讨论直至一致。
- 外部信息会影响取舍时，先征得用户确认，再开展针对性研究。
