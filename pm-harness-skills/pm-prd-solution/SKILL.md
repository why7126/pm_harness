# PM PRD Solution

把 `pm-prd-mvp` 已确认的需求范围转化为可评审、可追踪、可交给 `pm-prd-design` 的业务解决方案。通过持续反问、备选方案比较和决策记录完成收敛；未经用户确认不得冻结关键方案。

## 必读路由

- 每次运行先读 [operating-modes.md](references/operating-modes.md) 与 [solution-workflow.md](references/solution-workflow.md)。
- 拆解角色、场景、流程、对象、规则、权限、状态和异常时读 [solution-model.md](references/solution-model.md)。
- 产生或比较备选方案时读 [option-evaluation.md](references/option-evaluation.md)。
- 建立编号、决策、影响分析或 Patch 时读 [traceability-and-patch.md](references/traceability-and-patch.md)。
- 生成正式交付包前读 [output-contract.md](references/output-contract.md)。

## 所处链路与边界

遵循：`pm-prd-position → pm-prd-plan → pm-prd-mvp → pm-prd-solution → pm-prd-design`。

- 输入：MVP 基线、规划基线或一个边界明确的待解需求；最低必须明确业务问题、目标用户或角色、期望结果及约束。
- 输出：问题目标、角色场景、端到端流程、业务对象、业务机制、规则、权限、状态、异常边界、备选方案取舍、决策和设计交接基线。
- 禁止上探：重新定义产品定位、完整产品架构、里程碑、MVP 范围或功能优先级。发现冲突时记录影响并建议返回相应上游 Skill。
- 禁止下探：定义页面布局、具体字段、按钮位置、组件、视觉、详细交互、高保真原型、接口、数据库或技术架构。
- 核心判据：本 Skill 决定“业务应如何运转”；`pm-prd-design` 决定“如何通过界面和交互实现”。

## 核心工作流

1. 识别首次探索、重新收敛或局部 Patch，并校验最低输入。
2. 提取上游已确认结论、硬约束、事实、假设、待验证项和未决问题，建立保护基线。
3. 把笼统功能改写为“角色在场景中为实现结果而解决的问题”，确认成功标准。
4. 按主题分轮反问；每轮默认 1–3 个关键问题，提供互斥选项、推荐项、理由与主要风险，允许自由补充。
5. 依次收敛角色与场景、主流程、业务对象、机制规则、权限、状态生命周期、异常边界和跨模块影响；根据答案动态跳转和追问。
6. 对关键分歧至少提出两个可行方案；按用户价值、闭环完整性、一致性、复杂度、风险、可扩展性与上游约束比较。
7. 主动挑战隐含假设、职责混乱、规则冲突、越权路径、不可逆操作、极端情况和无法验收的表述。
8. 每个决策节点记录来源、选项、推荐、用户结论、理由、影响、条件和待验证项；不得把推荐自动当作确认。
9. 检查方案对 MVP 范围、依赖、成本、风险和其他模块的直接与连带影响；超出授权范围只给影响建议，不代替上游改基线。
10. 无阻断分歧后呈现方案摘要、未决项和冻结范围，取得用户明确确认。
11. 复制 `assets/baseline-templates/` 生成完整方案基线，运行校验；仅在用户明确要求 ZIP 时运行打包脚本。

## 强制规则

- 先问影响结论的关键问题，避免为了完整而机械穷举。
- 每轮推荐必须说明适用前提与主要风险；不存在可靠推荐时明确说明证据不足。
- 区分事实、上游决策、当前假设、用户确认、待验证项与建议，不得混写。
- 业务对象只定义业务语义、关系和生命周期，不设计数据表或接口。
- 权限同时覆盖主体、对象、动作、范围、条件和例外；状态同时覆盖进入、退出、守卫、回退和终态。
- 异常处理至少覆盖空、重复、并发、超限、失效、越权、中断、失败恢复与不可逆操作中适用的部分。
- 新需求或方案变更先分析直接与连带影响，再由用户决定纳入、延后、排除或返回上游。
- Patch 默认保护未授权区域；发现关联影响时先呈现影响并等待用户确认，不得顺手修改。
- 未决阻断问题存在时不得宣称正式收敛；可输出带条件的草案，但必须显著标记阻断项。

## 完成条件

仅当问题与目标、角色场景、主流程、业务对象、核心机制、规则、权限、状态、异常边界、方案取舍、关键决策、影响、验收意图和未决项均有明确结论，且无阻断性分歧，才可冻结方案。向 `pm-prd-design` 交接业务方案和约束，不越界补页面、字段、组件或视觉方案。

## 工具

```bash
python3 scripts/validate_solution_baseline.py <方案基线目录>
python3 scripts/package_solution_baseline.py <方案基线目录> [输出ZIP]
```

必须先校验成功。用户未明确要求 ZIP 时，不得仅因模板包含打包脚本就生成 ZIP。
