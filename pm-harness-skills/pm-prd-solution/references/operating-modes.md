# 运行模式

## 首次探索

适用于只有需求描述、MVP 功能条目或初步构想的情况。最低输入为业务问题、关键角色或目标用户、期望结果与已知约束。缺少上游包不必机械阻断，但要标记来源与假设。

## 重新收敛

适用于既有方案整体存在问题。最低输入为现有方案、重新讨论的原因和期望目标。先识别保留、废弃、待验证和冲突内容，再决定讨论范围；不得默认推翻全部结论。

## 局部 Patch

适用于只修改一项或少量已确认方案。最低输入为现有方案基线、明确修改点和修改原因。

1. 建立保护区和允许修改区。
2. 分析直接影响与连带影响。
3. 若必须扩大范围，列出新增修改项并取得确认。
4. 未授权内容保持不变。
5. 输出版本差异和回归检查。

## 模式冲突

- 标记 Patch 但要求整体重构：说明影响，确认转为重新收敛或缩小范围。
- 方案讨论实际改变目标用户、核心价值或产品边界：返回 `pm-prd-position`。
- 方案讨论实际改变完整架构或里程碑：返回 `pm-prd-plan`。
- 方案讨论实际改变 MVP 取舍或验证范围：返回 `pm-prd-mvp`。
- 用户已经要求页面、字段或原型：将已确认方案交给 `pm-prd-design`。
