# 备选方案评估

## 何时必须比较方案

- 存在多个合理职责归属、流程模式或业务机制
- 用户价值与治理、成本或风险冲突
- 当前方案会锁定长期结构或产生高迁移成本
- 用户明确要求比较 A/B/C 方案

## 比较维度

采用 1–5 分仅用于辅助解释，不替代判断：

| 维度 | 关注点 |
|---|---|
| 用户价值 | 是否更直接解决目标问题 |
| 闭环贡献 | 是否让端到端任务真正完成 |
| 一致性 | 是否符合定位、规划、MVP 与既有规则 |
| 认知与操作复杂度 | 对用户和运营是否易理解、易执行 |
| 实施与运营成本 | 是否引入显著持续成本或依赖 |
| 风险与可控性 | 越权、误操作、合规和失败后果 |
| 可扩展性 | 未来扩展是否需要推翻核心机制 |

## 推荐格式

对每个方案说明核心机制、适用前提、优势、代价、风险、影响范围和不可逆性。给出推荐时说明为何在当前约束下更合适，以及什么条件变化会导致推荐改变。

不得制造虚假选项。若只有一个合规可行方案，说明排除其他方案的原因；证据不足时先定义待验证项。
