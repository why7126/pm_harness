# 方案收敛工作流

## 1. 建立问题框架

确认谁在什么场景遇到什么问题、当前如何处理、期望结果、成功标准、不可违反的约束。把“增加某功能”转换为可验证的问题陈述。

## 2. 主题式反问

默认按下列主题推进，但允许动态跳转：

1. 目标与边界
2. 角色与核心场景
3. 主流程与关键节点
4. 业务对象与关系
5. 机制和业务规则
6. 权限与责任
7. 状态与生命周期
8. 异常、边界和恢复
9. 跨模块影响与验收意图

每轮只问最能改变方案的 1–3 个问题。选项应互斥、可比较；推荐项标注“推荐”，同时说明原因和风险。用户可以组合选项时明确允许组合。

## 3. 决策门

每个主题结束前检查：结论是否明确、是否与上游冲突、是否存在未验证假设、是否影响其他主题。关键结论需用户确认，普通推论可标记为建议。

## 4. 主动挑战

重点检查：

- 是否把内部组织便利置于用户任务之前
- 角色职责是否重叠或无人负责
- 是否存在绕过审批、权限或状态守卫的路径
- 删除、转让、撤销、失效等不可逆操作是否可恢复
- 正常流程是否依赖未定义的数据、组织或外部能力
- 规则在批量、并发、跨组织、历史版本和极端规模下是否仍成立
- 验收标准是否只描述“支持”，却无法判断成功

## 5. 冻结与交接

先展示方案摘要、核心取舍、未决项、风险及影响，再请求用户确认冻结。正式交付只能包含已确认结论；条件性内容必须注明触发条件和责任人建议。
