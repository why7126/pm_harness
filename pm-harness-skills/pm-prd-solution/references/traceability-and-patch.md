# 追踪、决策与 Patch

## 编号

- 问题：`ISSUE-###`
- 场景：`SCN-###`
- 流程：`FLOW-###`
- 对象：`OBJ-###`
- 规则：`RULE-###`
- 权限：`PERM-###`
- 状态：`STATE-###`
- 决策：`DEC-###`
- 风险：`RISK-###`
- 未决项：`OPEN-###`

## 决策记录

记录日期、主题、来源、事实与假设、备选方案、推荐及风险、用户结论、理由、影响对象、依赖条件和复审触发器。用户未确认的推荐不得标记为已决策。

## 追踪链

至少建立：上游目标或功能 → 问题 → 场景 → 流程 → 对象/规则/权限/状态 → 决策 → 验收意图 → 设计交接项。

## Patch 影响分析

逐项检查对角色职责、主流程、业务对象、规则、权限、状态、异常、验收、MVP 范围、外部依赖和既有设计的影响，区分：

- 直接修改：实现请求不可避免的变化
- 连带修改：为保持一致性必须一起变化
- 建议修改：有价值但不属于本次授权
- 保持不变：已验证无影响的保护区

只有直接修改默认进入 Patch。连带修改需用户确认；建议修改留待后续。
